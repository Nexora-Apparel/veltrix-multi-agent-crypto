# H3.1 transaction-scoped worker fencing — implementation status

## Current state

H3.1 code is implemented on `work/h1.1-h2-integration` and locally regression-tested. This document distinguishes local code/test evidence from the still-outstanding live Turso conformance gate.

## RunContext and orchestration

`veltrix/orchestration.py` now provides:

- `RunContext.owner_id`, `lease_name` and `fencing_token`;
- a preflight `assert_fence()` check;
- `assert_fence_in_transaction(db)`, which uses the caller's connection and validates the active, unexpired lease;
- cooperative deadline and item-budget enforcement;
- one attempt per invocation, idempotency and deferred retry semantics.

The transaction-scoped callback does not open a second connection. A stale or expired lease raises `LeaseBusy`.

## Fenced worker implementation

| Stage | Implementation | Durable mutation protected |
|---|---|---|
| Discovery | `discovery.py`, `launch_stream.py` | Candidate, feed-health and outage persistence |
| Initial enrichment | `enrichment.py` | Per-row claim, snapshot insert and completion/retry state |
| Market refresh | `market_refresh.py` | Per-row claim, append-only snapshot and completion/retry state |
| Risk evidence | `risk_worker.py`, `risk_store.py` | Per-row claim, report insert and completion/retry state |
| Consensus | `consensus_worker.py`, `consensus_store.py` | Per-row claim, decision insert and completion/retry state |
| Paper-only | `paper_trading.py`, `ledger.py` | Paper entry, skip/block outcome and exit-fill mutations |

The four queued workers persist `claimed_by_owner_id` and `claim_fencing_token` alongside their per-row lease expiry. Completion/failure must match the active claim. A reclaimed or expired row cannot be mutated by a stale worker.

Evidence stores and the paper broker expose caller-owned transaction methods. They do not commit or close a connection owned by the fenced worker.

Provider reads remain outside write transactions. Workers revalidate global and per-row ownership immediately before persistence. Lease loss is a stop condition; it is not translated into an ordinary provider failure.

## One-shot composition

`pipeline.py` composes:

1. bounded discovery;
2. initial enrichment;
3. market refresh;
4. risk evidence;
5. consensus;
6. optional paper-only processing.

The production builder disables the long-lived PumpPortal websocket supervisor. The paper stage is disabled by default and requires explicit configuration. It has no signer, exchange, wallet execution, transaction submission or broadcast path.

Default stage limits are 25 / 25 / 25 / 5 / 10 / 25. The default cooperative item budget is 150. One invocation performs at most one attempt; retries are deferred to a later invocation.

## Remote conformance gate

The manual workflow `.github/workflows/turso-remote-conformance.yml` now runs:

- remote Turso DB-API behaviour;
- application schema initialization for all stores and workers;
- orchestration fencing and recovery;
- worker-level transaction-scoped fencing and row-claim checks.

All destructive schema cleanup is restricted to the exact disposable host `veltrix-h0-conformance.turso.io`. The workflow requires dedicated secrets:

- `TURSO_CONFORMANCE_DATABASE_URL`;
- `TURSO_CONFORMANCE_AUTH_TOKEN`.

Do not substitute production `TURSO_DATABASE_URL` or `TURSO_AUTH_TOKEN`.
