# H1.1 + H2 integration baseline

## Branch ancestry

- H2 source: `work/h2-fencing-hardening` at `bc3cfa7a65401df67de6873f6cdaf1971b255d74`.
- H1.1 source: `work/h1.1-worker-database-adapter` at `d1931c8979a51f0e99a2e20a04f38ba87218f469`.
- Integration branch: `work/h1.1-h2-integration`.

The integration branch starts at the H2 head and imports only the four H1.1 worker-adapter files plus the H1.1 adapter regression test. This avoids overwriting H2's stronger remote-conformance guardrails with the earlier H1.1 versions.

## Current limitations

This is an integration baseline, not a completed worker-fencing implementation. Worker `run_once()` methods still need a transaction-scoped `RunContext` fence and per-row claim identity. H1.2 remote conformance has not run because dedicated disposable Turso credentials have not been verified.

## Validation gate

Run full Python CI against this combined branch. Then run the manual remote conformance workflow only after the exact disposable database and dedicated credentials are verified. Do not merge the integration PR or compose the production pipeline until both gates pass.
