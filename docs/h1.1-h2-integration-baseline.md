## Integrated implementation

- Shared database adapter used by enrichment, market refresh, risk and consensus workers.
- Transaction-scoped global fencing and per-row owner/token claim identity across discovery, enrichment, market refresh, risk evidence, consensus and optional paper-only mutations.
- One-shot stage composition with bounded batches, one attempt per invocation, stable idempotency and deferred retries.
- Optional paper-only stage is disabled by default and uses only the existing paper ledger.
- Production discovery builder disables the long-lived PumpPortal websocket supervisor for ephemeral runs.

See:
- `docs/h3-one-shot-pipeline-contract.md`
- `docs/h3.1-worker-fencing-implementation-status.md`

## Remote conformance

The default-branch workflow `.github/workflows/turso-h3-remote-conformance.yml` checks out a pinned clean integration commit and requires dedicated disposable secrets targeting exactly `veltrix-h0-conformance-test-nexora-apparel.aws-eu-central-1.turso.io`. The legacy workflow using generic `TURSO_DATABASE_URL` / `TURSO_AUTH_TOKEN` was removed from the clean branch.

The source integration commit passed local GitHub Actions CI, but that result is not transferable to the clean branch. Current-head CI and remote conformance must pass independently. Local SQLite CI is not evidence of remote Turso compatibility.

## Release gate

Keep PR #22 in draft. Do not merge, deploy, activate a scheduler, or enable paper processing until current-head CI is green and live H1.2/H2 Turso conformance passes. Cloudflare API/dashboard, domain, DNS, HTTPS, scheduler, monitoring and recovery remain later workstreams.
